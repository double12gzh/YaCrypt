# Harness 自进化流程（RSI）

本目录保存每周 Harness 蒸馏的事实入口。目标不是写更多规则，而是让下一次同类失败在门禁里直接失败。

## 每周一次

1. **收集**：本周 `git log`（含各任务分支，不只看 `main`）、已完成 Issue 与其评论线程、`docs/tasks/` 下的复盘与验收记录。
   计数单位是**被记录到的事件**（一次失败 / 一次驳回 / 一次告警），不是 grep 命中或主观印象。
2. **归类**：把事件合并成失败模式，按"是否会被同一原因再次触发"排序，记录证据链接与计数。
3. **固化**，按优先级：
   - **机器检查**（首选）：能在 `scripts/` 里断言的，写成 `test_*.py` 并接入 `scripts/verify.sh`。
     断言必须能在**旧实现/旧配置**上失败，并给出反证输出。
   - **规则**：写入 `AGENTS.md` §1.7，分配未占用的 `H-xx`。ID 是身份，节号可以随合并重排。
   - **清单**：更新 `.agents/skills/check/SKILL.md` 的判据与三态定义。
   - **教训**：只在有证据时写 `LESSONS.md`；重复出现才晋升为工程规范。
4. **周报**：写 `docs/harness/<YYYY-MM-DD>.md`，包含扫描范围、事件计数、已固化项、反证、未固化原因。

## 纪律

- 同一周的两个并行分支都可能改 `AGENTS.md`，所以规则用 `H-xx` 标识；`scripts/test_harness.py`
  强制节号连续、ID 不重复、技能文件存在。
- 规则要落到**会合并的基线分支**。只停留在未合并任务分支的规则不会影响任何后续 Agent，等同于没写。
- 不给"靠人记住"的规则记账为已固化。没有机器检查时，必须在周报的"未固化"里写明原因与升级条件。
- 周报不美化：`cargo deny` 的 warning、未运行平台、被 watchdog 中断的会话都原样记录。
