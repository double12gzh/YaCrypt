# 第一阶段协作流程

适用于 agy / Codex / pi / omp；工具只负责执行，项目文件保存任务和知识。
本阶段手动启动会话，无自动领取、定时运行、自动合并或发布。

1. 协调者复制 [任务卡](templates/task.md) 到 `docs/tasks/<id>.md`，写清来源、目标、验收、
   风险、base SHA、路径范围、owner、时间/重试预算与权限。无验收条件不进入就绪。
2. 实现者在独占 worktree 核实分支、读取规范/教训/子系统源码，修改并运行完整门禁。
   输出补丁/提交和证据，将状态改为待独立验收；自己不能声明独立通过。
3. 独立会话按任务契约复查实际版本、调用链和证据，必要时重新运行或注入故障。
   使用 [验收报告](templates/acceptance.md)，返回 PASS / ISSUES / BLOCKED。
   ISSUES 返回原 owner 修复；新提交需要重新验收。两轮仍失败时重新判断范围和环境。
4. 验收通过进入待人工集成。集成者获得授权后在最新基线集成并重新验证，记录实际版本。
   未合并可结束本阶段演练，但状态必须保持待人工集成，不能写成已交付或已发布。
5. 使用 [复盘模板](templates/retrospective.md) 记录发生过的失败、原因和改进。
   只将有证据的教训写入 LESSONS，严重问题立即约束；一般规则重复出现后再晋升。

状态：就绪 → 实现中 → 待独立验收 → 待人工集成 → 已合并；另有阻塞/取消。
角色可换工具，作者与验收者需独立会话。验收者只写自己的报告，不修改作者代码。
日志只保留测试材料，不包含真实口令/私钥。默认并行实现不超过 2，完整重测试串行。
