# 工程规范

1. 一个任务对应一个可观察目标，明确非目标和允许修改范围。先看源码再相信文档摘要。
2. 修改调用链中的契约时检查 CLI、TUI、core 及同类失败路径，同一变更更新子系统文档。
3. 修复包含能暴露原问题的行为检查；测试用临时数据，清理自己启动的资源。
4. 完整质量门禁只由 `scripts/verify.sh` 定义，所有交付入口调用它；失败保留证据。
5. 验收者独立于实现会话，结论绑定版本。追加代码或 rebase 后重新验证最终候选版本。
6. 同一 worktree 只有一个写入者，独立日志和构建目录；集成串行。
7. 安全不变量见 AGENTS.md；变更加密格式、信任规则、覆盖语义或放宽门禁需单独授权和审查。
8. 合并/发布与本地实现分开记录；未执行项显式列出，不能用计划代替运行结果。

规则来自可追溯事件时链接 LESSONS；能机械判断的规则优先变成测试或脚本。
