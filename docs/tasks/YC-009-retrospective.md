# YC-009：从质量证据到产品回归

本轮新增 `diagnose → propose → approve → tick` 入口。诊断运行统一门禁并保存版本、退出码、失败阶段和日志哈希；提案只产生任务卡，批准绑定干净 HEAD、正文哈希、精确路径和验收要求。原两种确定性探针仍可自动处理，产品任务需要显式批准；环境/未知/高风险范围只报告。

## 实际任务来源

在 772b1a0 的未改动产品代码上，临时 TestBackend 复现了 80×12 文件浏览器的选中项不可见：选中 item_04.txt，画面只显示到 item_01.txt。既有测试只验证无崩溃，没有断言选择可见性。
新增入口在 940b2ea 运行完整门禁得到 PASS。随后把独立复现的覆盖缺口和这份通过的诊断一起提交为 QP-f9cdaa40e2b1456a，而不是虚构基线门禁失败。协调器按用户批准的本轮范围，显式批准三个 UI/测试/接口文档文件，进入 EV-265392763f90。

## 实际执行与恢复

pi 使用 magpie/agentrouter/gpt-6.1-sol 写出 UI 修复、七项视口回归和接口文档。首轮 900 秒超时，运行器停止进程组并保留草稿；没有把超时回执改成成功。
协调器没有代改产品实现：保存草稿字节及哈希，完整验证通过后提交 ce73ae9；再显式授予一次 600 秒 pi 完成确认。该会话成功返回，源码保持不变，得到有效执行快照后才 submit。之后通过 resume --recheck 明确追加一次 omp 独立验收，使用 magpie/amd/DeepSeek-V4.1-Flash。
第一次 omp 验收遇到 AMD TokenFactory unexpected EOF，未产生结论；协调器检查失败原因和未变化的源码后，显式追加一次 600 秒同提交验收。
第二次 omp 仍因上游 stream terminated 失败，没有验收结论。停止该服务重试后，显式选择此前已获用户授权的 agy/claude-sonnet-5-5-medium 进行同提交独立验收；原 policy 保留在 cycle.json，默认模板仍是 omp，未静默修改配置。
总计五次模型会话：一次实现超时、一次完成确认、两次连接失败的 omp 验收、一次明确选择的 agy 验收。它不是默认两会话内的全自动成功，也不是自动无限重试。原超时、操作者恢复原因、全部回执和草稿都保留。

## 防复发证据

- pi 新增的永久回归在旧渲染器上产生行为失败；不是编译错误。
- 最初的归档复现在 pi 修复上通过。
- 完整门禁覆盖导航、缩小/放大、Unicode/长名称、极小视口、空列表以及选择后完整路径和原操作选项的保留。
- 真实 PTY 在 80×12 窗口进入 Encrypt/File browser，向下移动并缩放，完整重绘后观察到选中标记与 item_04.txt，Esc/q 正常退出。最初按原始增量输出搜索完整文件名的方法不适用于 Ratatui 差分绘制，检查脚本改为触发完整缩放重绘；此处没有修改产品代码以迎合测试。

框架由独立 Codex 会话审查，产品由真实 pi 实现，omp 两次尝试因服务故障未给出结论，最终独立验收使用 agy/Claude。没有对服务内部模型身份作额外认证；精确路由和原始输出哈希见归档回执。

## 当前边界

`watch` 运行原固定扫描器和已批准 backlog，不会每轮自动运行昂贵的完整 diagnose。diagnose/propose/approve 是显式入口；未安装常驻调度。批准者字段是本机操作者声明，不是身份认证；路径白名单不等于语义安全证明，密码学等专项变更仍需另外审查。
代码与事实复盘写回候选分支；main 合并和 push 仍由本轮已获授权的协调器交付，不属于自动循环权限。详见 [验收](YC-009-acceptance.md) 和 [证据清单](evidence/YC-009/manifest.json)。
